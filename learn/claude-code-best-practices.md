# Claude Code 大型项目最佳实践

> 视频来源：https://v.douyin.com/BLNYjuFIGeY/

## 核心理念

Claude 官方博客强调：**决定成败的不是模型本身，而是 Harness**。

Harness（鞍具）是指给 AI 编程工具搭建的良好生态环境。就像一匹好马需要好的鞍具才能发挥潜能，Claude Code 配置好生态环境后，才能发挥更大作用。

---

## 组件架构

Claude Code 的生态环境包含 **5 个核心组件** 和 **2 个扩展组件**：

```
┌─────────────────────────────────────────────────────────┐
│                    Claude Code 生态环境                   │
├─────────────────────────────────────────────────────────┤
│  核心组件（常用）                                          │
│  ├─ CLAUDE.md    全局上下文、规范约束                       │
│  ├─ Hooks        生命周期钩子、自动化行为                    │
│  ├─ Skills       按需加载的专用知识/流程                     │
│  ├─ Plugins      团队分发机制                              │
│  └─ MCP          外部系统连接                              │
├─────────────────────────────────────────────────────────┤
│  扩展组件                                                 │
│  ├─ LSP          代码导航、快速定位                        │
│  └─ 子代理        独立执行子任务                            │
└─────────────────────────────────────────────────────────┘
```

## 一、CLAUDE.md

### 1.1 作用

CLAUDE.md 是**每次对话都会被加载到上下文**的文件，非常重要。

**用途：**
- 定义全局规范
- 避免常见陷阱
- 重点说明容易犯错的地方

**常见误区：**
❌ 把复用的知识流程放进 CLAUDE.md（作用很小）  
✅ 应该提取出来形成 Skill

### 1.2 分层设计原则

```
项目根目录/
├── CLAUDE.md              # 第一层：全局规范（保持简洁）
├── .claude/
│   └── code-map.md        # 第二层：代码导航索引
├── src/
│   ├── payments/
│   │   └── CLAUDE.md      # 第三层：支付模块约束
│   ├── api/
│   │   └── CLAUDE.md      # 第三层：API 模块约束
│   └── ...
```

| 层级 | 文件位置 | 内容 |
|------|----------|------|
| 根目录 | `/CLAUDE.md` | 全局规范、最重要的指针和陷阱 |
| Code Map | `.claude/code-map.md` | 代码库导航索引 |
| 子目录 | `src/xxx/CLAUDE.md` | 该模块的本地约定和约束 |

### 1.3 加载顺序

```
1. 加载根目录 CLAUDE.md（全局规范）
      ↓
2. 根据任务需求，读取 Code Map 了解模块分布
      ↓
3. 定位到具体模块后，加载该模块的子目录 CLAUDE.md
      ↓
4. 形成完整的上下文约束
```

### 1.4 分层的好处

**避免上下文污染：**
- 不分层：所有约束都放根目录，每次对话都加载无关内容
- 分层后：按需加载，只加载与当前任务相关的约束

**示例：**
```
# 错误做法 - 根目录 CLAUDE.md 包含所有内容
- 支付模块约束...
- API 模块约束...
- 数据库约束...
（每次对话都加载，浪费上下文）

# 正确做法 - 分层
根目录 CLAUDE.md: 只写全局规范
src/payments/CLAUDE.md: 只写支付相关约束
src/api/CLAUDE.md: 只写 API 相关约束
（按需加载，精准高效）
```

## 二、Hooks

### 2.1 什么是 Hooks

在 Claude Code 对话过程中，会触发不同的**生命周期事件**：
- 发起对话 → 触发起始钩子
- 完成对话 → 触发结束钩子

钩子触发时会调用对应的自定义代码。

### 2.2 适用场景

| 场景 | 说明 |
|------|------|
| 代码格式化 | 对话完成后自动格式化代码 |
| 代码检查 | 自动执行 lint、测试等 |
| 可视化代码 | 生成图表、文档 |
| **捕获对话学习** | 总结对话经验，沉淀知识 |

### 2.3 核心价值：自净化学习

**最关键的应用场景：捕获对话学习**

```
对话完成
    ↓
触发 Hook
    ↓
总结本轮对话
    ↓
提炼经验教训
    ↓
沉淀为 Skill 或 CLAUDE.md 约束
    ↓
Claude Code 下次不再犯同样错误
```

### 2.4 最佳实践

⚠️ **不要每次对话后都总结** — Token 消耗很大

✅ **建议做法：**
- 累积多轮对话后再总结（如 10 轮）
- 总结范围越广，经验越有通用性

## 三、Skills

### 3.1 什么是 Skills

Skills 是**按需加载**的知识包，用于固化专用知识或固定流程。

### 3.2 设计理念：渐进式披露

```
提示词包含技能描述和触发场景
      ↓
匹配到触发场景时
      ↓
加载该 Skill 到上下文
      ↓
执行 Skill 定义的流程
```

### 3.3 两大目的

| 目的 | 说明 |
|------|------|
| **减少上下文占用** | 只在需要时加载，按需披露 |
| **返回结果确定** | 按预定义流程执行，结果可控可预期 |

### 3.4 示例：安全审查 Skill

```
触发条件：用户请求安全审查
      ↓
加载 security-review Skill
      ↓
执行预定义流程：
  1. 检查输入验证
  2. 检查权限控制
  3. 检查敏感数据处理
  4. ...
      ↓
返回标准化审查报告
```

由专业的安全审查员编写 Skill，AI 执行时既专业又规范。

## 四、Plugins

### 4.1 核心价值：分发

Plugins 用于**团队协作和分发**：
- 打包 Hooks、Skills、子代理
- 一行命令安装
- 快速分发给团队成员

### 4.2 类比

类似于：
- Java 的 Maven 私服
- Node.js 的 npm 私有仓库
- Python 的私有 PyPI

**适合场景：** 企业内部统一基建，快速分发能力。

## 五、MCP（Model Context Protocol）

### 5.1 什么是 MCP

MCP 用于**连接外部系统**，让 Claude Code 能与企业内部系统交互。

### 5.2 应用场景

```
┌─────────────────────────────────────────────────────────┐
│                    企业内部系统                           │
├─────────────────────────────────────────────────────────┤
│  工单系统    产品系统    测试系统    运维系统              │
└───────────────────────┬─────────────────────────────────┘
                        │
                        │ MCP 连接
                        │
                        ▼
              ┌─────────────────┐
              │   Claude Code   │
              │   (AI Agent)   │
              └─────────────────┘
```

### 5.3 自动化流程示例

```
1. 测试人员在工单系统提交 Bug
2. Claude Code 通过 MCP 拉取未处理工单
3. AI 读取工单详情（标题、描述、截图）
4. AI 定位并修复问题
5. AI 将结果推送至运维系统
```

通过 MCP，整个流程完全自动化。

### 5.4 替代方案

也可以使用 CI/CD 平台（如飞书、钉钉）实现类似能力。

## 六、LSP（Language Server Protocol）

### 6.1 为什么需要 LSP

**没有 LSP：**
```
AI 需要搜索每个文件 → 逐个匹配 → 非常慢且消耗 Token
```

**安装 LSP 后：**
```
像 IDE 一样点击跳转 → 精准定位 → 极速检索
```

### 6.2 LSP 的作用

| 功能 | 说明 |
|------|------|
| **代码导航** | 点击函数名，跳转到定义 |
| **自动错误检测** | 实时发现语法和类型错误 |

### 6.3 安装步骤

1. 安装官方 Claude 插件
2. 切换到 **Discover** 面板
3. 搜索对应语言的 LSP（如 Java 搜索 `jdtls`）
4. 安装到全局（推荐）

## 七、代码库搜索优化

### 7.1 Claude Code 的工作流程

```
1. 读取 CLAUDE.md
      ↓ 了解项目架构、关键陷阱、代码约定
2. 遍历文件系统
      ↓ 找到相关目录和代码
3. 阅读源码
      ↓ 理解业务逻辑
4. 修改代码
```

**前三步最重要：**
- 第一步：定义"不能做什么"
- 第二步：定义"去哪里找"
- 第三步：定义"怎么理解"

### 7.2 Code Map：代码库的索引

**问题：** 大型项目搜索慢，像数据库全表扫描

**解决方案：** 建立 Code Map（类似数据库索引）

```
# Code Map 示例 (code-map.md)

## 项目结构

### 支付模块 (src/payments/)
- payment.service.ts    # 支付核心服务
- billing.controller.ts  # 账单控制器
- invoice.model.ts       # 发票数据模型

### 用户模块 (src/users/)
- auth.service.ts        # 认证服务
- profile.controller.ts  # 用户资料
- user.model.ts          # 用户模型

### API 模块 (src/api/)
- routes/               # 路由定义
- middleware/           # 中间件
- validators/           # 参数校验
```

### 7.3 使用方式

在根目录 `CLAUDE.md` 中声明：

```markdown
## 代码结构

在执行代码搜索前，请先阅读 `.claude/code-map.md` 了解项目模块分布。
```

### 7.4 三层协同

```
┌─────────────────────────────────────────────────────────┐
│  第一层：根目录 CLAUDE.md                                  │
│  内容：全局规范、最重要的指针和陷阱                          │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  第二层：Code Map                                         │
│  内容：代码库模块索引，快速定位目标模块                      │
└───────────────────────┬─────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│  第三层：子目录 CLAUDE.md                                  │
│  内容：该模块的具体约束和规范                               │
└─────────────────────────────────────────────────────────┘
```

**效果：** 搜索效率极高，不会迷路。

## 八、维护与更新

### 8.1 为什么需要定期维护

模型在不断进步：
- 旧版本需要约束的问题，新版本可能已修复
- 常用的解决方案可能被新版本内置

**原则：** 模型越强，CLAUDE.md 内容越少；模型越弱，需要约束的越多。

### 8.2 维护周期

| 时间点 | 操作 |
|--------|------|
| 新模型发布后 | 检查配置是否需要精简 |
| 每隔 3-6 个月 | 定期审查和优化 |

## 十、总结

这些最佳实践不仅适用于 Claude Code，也适用于任何 AI 编程工具：

| 核心要点 | 说明 |
|----------|------|
| **Harness 决定成败** | 模型只是基础，生态环境才是关键 |
| **分层 CLAUDE.md** | 根目录全局 + 子目录本地，避免污染 |
| **Code Map 加速** | 像数据库索引一样加速代码搜索 |
| **Hooks 自净化** | 累积经验，让 AI 越来越聪明 |
| **Skills 固化流程** | 按需加载，结果可控 |
| **定期维护** | 适应模型进步，精简配置 |
