# Claude Code 扩展：效率翻倍实战指南

> 视频来源：https://v.douyin.com/K42ewirTcXs/

## 扩展体系全景图

Claude Code 扩展分多层，每层解决不同问题：

```
┌─────────────────────────────────────────────────────────┐
│                 Claude Code 扩展体系                      │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  CLAUDE.md ─────── 长期记忆，每个会话自动加载              │
│                                                          │
│  Skills ────────── 自定义技能包，如 /deploy 跑部署流程      │
│                                                          │
│  MCP ───────────── 连接外部服务（查数据库、发 Slack 等）    │
│                                                          │
│  Subagents ─────── 把复杂任务拆成小块，隔离处理             │
│                                                          │
│  Agent Teams ───── 多个独立会话，互相协调                  │
│                                                          │
│  Hooks ─────────── 特定事件自动触发脚本                    │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

## 一、触发器清单：何时添加扩展

官方建议：**按需添加，别一上来折腾全套**。

| 场景 | 应该添加 | 示例 |
|------|----------|------|
| Claude 两次搞错项目约定 | **CLAUDE.md** | 总是用 `npm` 而不是 `pnpm` |
| 第三次粘贴同一套多步骤流程 | **Skill** | 部署流程、代码审查清单 |
| 一直从浏览器复制数据给 Claude | **MCP** | 连接数据库、API |
| 辅助任务输出刷爆对话窗口 | **Subagent** | 大规模文件读取、研究任务 |
| 希望每次自动发生，不用问 | **Hook** | 提交前跑测试、保存后格式化 |

**核心原则：重复 3 次 = 该封装成扩展**

## 二、概念辨析：避免踩坑

### 2.1 Skills vs Subagents

| 对比项 | Skills | Subagents |
|--------|--------|-----------|
| **本质** | 可复用的知识/工作流 | 隔离的工作线程 |
| **调用方式** | 随时调用，如 `/deploy` | 自动派发，只返回摘要 |
| **上下文影响** | 加载到当前对话 | 完全隔离，不污染主对话 |
| **适用场景** | 流程封装、知识参考 | 读大量文件、研究任务 |

**关键区别：Skills 是知识，Subagents 是劳动力。**

### 2.2 CLAUDE.md vs Skills

| 对比项 | CLAUDE.md | Skills |
|--------|-----------|--------|
| **加载时机** | 每个请求都加载 | 只在调用时加载 |
| **内容性质** | 永远要记住的事 | 偶尔需要参考的 |
| **适用内容** | 构建命令、项目结构 | API 文档、部署清单 |
| **长度限制** | ≤ 200 行，长了就拆 | 无严格限制 |

**经验法则：CLAUDE.md 保持 200 行以内，长了就拆成 Skill 或 reuse 文件。**

### 2.3 Subagent vs Agent Team

| 对比项 | Subagent | Agent Team |
|--------|----------|------------|
| **工作方式** | 当前会话里的临时工 | 多个独立的 Claude 会话 |
| **协作模式** | 干完汇报结果 | 能互相发消息，自我协调 |
| **适用场景** |一个人能干完的任务 | 需要团队协作的任务 |

### 2.4 Hook vs Skill

| 对比项 | Hook | Skill |
|--------|------|-------|
| **是否需要 Claude 思考** | ❌ 不需要 | ✅ 需要 |
| **性质** | 确定性自动化 | 需推理的工作流 |
| **示例** | 保存后自动格式化 | 代码审查清单 |

**一句话总结：Hook 是不需要 Claude 思考的自动化，Skill 是需要 Claude 推理的工作流。**

## 三、黄金组合：MCP + Skill

**MCP 给 Claude Code 能力，Skill 教 Claude 怎么用好能力。**

```
┌─────────────────────────────────────────────────────────┐
│  MCP ────────────────────────────────────────────────── │
│  负责连接工具                                            │
│  如：连接数据库、连接 Slack                               │
└───────────────────────┬─────────────────────────────────┘
                        │
                        │ 配合使用
                        │
┌───────────────────────▼─────────────────────────────────┐
│  Skill ──────────────────────────────────────────────── │
│  负责教会 Claude 使用方法                                │
│  如：数据库架构、常用查询模式、消息格式规范                 │
└─────────────────────────────────────────────────────────┘
```

**两者搭配，效果翻倍。**

## 四、强制规则：用 Hook 拦截

有些规则不能只写在 CLAUDE.md 当建议，要用 Hook 强制拦截。

**示例：绝对不能碰 `.env` 文件**

```
❌ 错误做法：只在 CLAUDE.md 里写 "不要修改 .env 文件"
✅ 正确做法：用 PreToolUseHook 拦截，直接阻止操作
```

## 五、多级别定义与冲突处理

扩展可在多个级别定义：

```
用户级 ───── 全局生效
项目级 ───── 当前项目生效
插件级 ───── 插件范围内生效
子目录级 ─── 嵌套生效
```

**冲突处理原则：更具体的说明优先**

| 扩展类型 | 冲突处理规则 |
|----------|--------------|
| CLAUDE.md | 子目录覆盖根目录通用规则 |
| Skills / Subagents | 按名称覆盖 |
| MCP 服务器 | 有优先级顺序 |
| Hooks | **所有匹配的 Hook 都会触发，不互相覆盖** |

## 六、上下文成本分析

**每个功能都会消耗 Claude 的上下文窗口，别贪多。**

| 扩展类型 | 上下文成本 | 说明 |
|----------|------------|------|
| **CLAUDE.md** | ⭐⭐⭐⭐⭐ 最高 | 每个请求都加载 |
| **Skills** | ⭐⭐ 低 | 只在调用时加载完整内容，平时只加载描述 |
| **MCP** | ⭐ 最低 | 工具默认启用搜索，空闲时几乎不占资源 |
| **Subagents** | ⭐ 零 | 完全隔离，不影响主对话 |
| **Hooks** | ⭐ 最低 | 事件触发时才执行 |

**风险提示：**
- 上下文塞满 → 增加噪音 → Claude 效率下降
- 可能触发错 Skill、忘记约定
