```
┌─────────────────────────────────────────────────────────────┐
│                    Claude Code 启动流程                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   ┌─────────────────────────────────────┐                   │
│   │        第一阶段：必读文件            │                   │
```

### 2.2 重要概念

> ⚠️ **关键提醒**：必读 ≠ 存在
>
> 这些配置文件**默认都是空的**，如果你不主动创建，Claude 每次对话都从零开始！

### 2.3 配置层级

| 层级 | 路径 | 作用范围 | 优先级 |
|------|------|----------|--------|
| **系统级** | `~/.claude/` | 所有项目 | 低 |
| **项目级** | `.claude/` 或项目根目录 | 当前项目 | 高 |

**优先级规则**：项目级配置会覆盖系统级配置

## 三、核心配置文件详解

### 3.1 settings.json — 权限、工具、钩子

**作用**：控制 Claude 的行为边界和自动化流程

```json
{
  "hooks": {
    "preCommit": "npm test",
    "prePush": "npm run lint"
  },
  "permissions": {
    "deny": ["rm -rf", "format", "git push --force"],
    "allow": ["git", "npm", "go", "docker"]
  },
  "tools": {
    "enabled": ["Bash", "Read", "Write", "Edit"],
    "disabled": []
  }
}
```

**常见配置项**：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| `hooks.preCommit` | 提交前执行 | 自动运行测试 |
| `hooks.prePush` | 推送前执行 | 自动 lint 检查 |
| `permissions.deny` | 禁止操作 | 禁止 rm -rf |
| `permissions.allow` | 允许操作 | 允许 git 操作 |

### 3.2 CLAUDE.md — 任务背景与偏好

**作用**：告诉 Claude 你是谁、做什么、偏好是什么

```markdown
# 项目背景

## 我是谁
- 独立开发者
- 主要技术栈：Go、TypeScript、React
- 英语水平：一般，偏好中文输出

## 项目说明
- 这是一个代码流程分析工具
- 输出目录：/data/caidanfeng/project/doc/mm-doc/learn/

## 输出偏好
- 使用中文注释
- 代码注释率 > 30%
- 函数长度 < 50 行
- 测试覆盖率 > 80%

## 禁止事项
- 不要使用中文变量名
- 不要提交敏感信息
- 不要跳过测试
```

### 3.3 rules.md — 规则与标准

**作用**：定义硬性规则，Claude 必须遵守

```markdown
# 项目规则

## 代码质量

- 测试覆盖率 ≥ 80%
- 所有 public 函数必须有文档注释
- 使用 golangci-lint 检查，零警告
- 代码复杂度 < 15

## 安全规范

- 禁止提交密钥、token、password
- 敏感配置使用环境变量
- SQL 查询必须使用参数化
- 用户输入必须验证

## 提交规范

- commit message 遵循 Conventional Commits
- PR 标题格式：`[类型] 简短描述`
- PR 必须通过 CI 检查
- 代码必须经过 Review

## 类型说明

- feat: 新功能
- fix: 修复 bug
- docs: 文档更新
- refactor: 重构
- test: 测试相关
```

### 3.4 memory.md — 记忆存储

**作用**：记录需要持久化的信息

```markdown
# 记忆存储

## 用户偏好

- 偏好函数式编程风格
- 喜欢详细的代码注释
- 偏好小步提交

## 项目状态

- 当前版本：v1.2.0
- 下一步计划：添加缓存支持
- 已解决问题：
  - 2024-01-15: 修复了内存泄漏问题

## 经验教训

- 2024-01-10: 不要在循环中执行数据库查询
- 2024-01-12: 并发操作必须加锁
```

## 四、ECC 项目功能介绍

### 4.1 项目背景

- **名称**：Everything Claude Code (ECC)
- **荣誉**：Anthropic 官方黑客松冠军
- **Stars**：15.6万（Claude Code 生态第一名）
- **内容**：作者10个月每天使用 Claude Code 的配置沉淀

### 4.2 六大核心功能

| 功能 | 痛点解决 | 技术实现 | 价值 |
|------|----------|----------|------|
| **自动记忆进化** | 重复犯错 | Instincts Memory | ⭐⭐⭐⭐⭐ |
| **先研究后动手** | 盲目修改 | research-first 工作流 | ⭐⭐⭐⭐ |
| **自动安全扫描** | 密钥泄露 | Hooks + Rules | ⭐⭐⭐⭐⭐ |
| **子代理并行** | 上下文污染 | 47+ Agents | ⭐⭐⭐⭐ |
| **工作流一键触发** | 重复操作 | 156 Skills | ⭐⭐⭐⭐ |
| **上下文智能压缩** | Token 爆窗 | Context Budget | ⭐⭐⭐ |

### 4.3 功能详解

#### 4.3.1 自动记忆进化

**原理**：纠正一次 → 自动记录 → 下次不再犯

```
用户纠正 → Instincts Memory 捕获 → 转化为技能 → 永久生效
```

#### 4.3.2 先研究后动手

**流程**：
```
复杂任务 → 查代码 → 查文档 → 制定方案 → 开始执行
```

**实现**：`/research-first` 技能

#### 4.3.3 自动安全扫描

**检查项**：
- 密钥扫描（AWS Key、API Token 等）
- Linter 检查
- 敏感文件检测

**实现**：Hooks + Rules 联合

#### 4.3.4 子代理并行

**场景**：
- 代码审查
- 调研任务
- 多文件修改

**优势**：主对话上下文不被污染

#### 4.3.5 工作流一键触发

**常用命令**：
- `/tdd` — 测试驱动开发
- `/commit` — 规范化提交
- `/review` — 代码审查

#### 4.3.6 上下文智能压缩

**原理**：监控 Token 消耗 → 接近上限 → 自动压缩

## 五、最小可用配置

### 5.1 目录结构

```
~/.claude/                    # 系统级配置
├── settings.json             # 全局权限
├── CLAUDE.md                 # 个人偏好
└── memory.md                 # 经验积累

项目根目录/
├── .claude/
│   ├── CLAUDE.md             # 项目背景
│   ├── rules.md              # 项目规范
│   └── memory.md             # 项目记忆
├── agents/                   # 子代理（可选）
├── skills/                   # 技能包（可选）
└── commands/                 # 自定义命令（可选）
```

### 5.2 快速开始

**步骤 1**：创建系统级配置

```bash
mkdir -p ~/.claude
```

**步骤 2**：创建 `~/.claude/CLAUDE.md`

```markdown
# 个人偏好

## 技术栈
- 语言：Go, TypeScript
- 框架：React, Gin
- 数据库：PostgreSQL, Redis

## 输出偏好
- 语言：中文
- 代码注释：详细
- 提交粒度：小步提交
```

**步骤 3**：创建项目级配置

```bash
mkdir -p 项目根目录/.claude
```

**步骤 4**：创建 `项目/.claude/rules.md`

```markdown
# 项目规则

## 代码规范
- 测试覆盖率 > 80%
- 代码注释率 > 30%

## 安全规范
- 禁止提交密钥
- 环境变量管理敏感信息
```

## 六、进阶配置示例

### 6.1 完整 settings.json

```json
{
  "version": "1.0",
  "hooks": {
    "preCommit": "npm run test && npm run lint",
    "prePush": "npm run security-check",
    "postMerge": "npm install"
  },
  "permissions": {
    "deny": [
      "rm -rf",
      "git push --force",
      "format",
      "DROP TABLE"
    ],
    "allow": [
      "git status",
      "git diff",
      "git log",
      "npm run",
      "go test",
      "docker ps"
    ]
  },
  "context": {
    "maxTokens": 200000,
    "compressionThreshold": 0.8
  },
  "agents": {
    "parallel": true,
    "maxConcurrent": 5
  }
}
```

### 6.2 完整 CLAUDE.md

```markdown
# 项目配置

## 关于我
- 角色：独立开发者
- 经验：5年后端开发
- 语言偏好：中文沟通，英文代码

## 技术栈
- 后端：Go, PostgreSQL, Redis
- 前端：React, TypeScript
- 部署：Docker, Kubernetes

## 项目说明
这是一个代码分析工具，用于生成代码流程文档。

## 输出规范
- 注释语言：中文
- 注释率：> 30%
- 函数长度：< 50 行
- 测试覆盖率：> 80%

## 工作偏好
- 提交粒度：小步频繁提交
- 分支策略：feature 分支开发
- 代码审查：必须经过审查

## 禁止事项
- ❌ 中文变量名
- ❌ 提交敏感信息
- ❌ 跳过测试
- ❌ 强制推送主分支
```

### 6.3 完整 rules.md

```markdown
# 项目规则

## 代码质量规则

### 必须遵守
- [ ] 测试覆盖率 ≥ 80%
- [ ] 所有 public 函数必须有文档注释
- [ ] 代码复杂度 < 15
- [ ] 零 linting 错误

### 代码风格
- 使用 prettier 格式化
- 使用 eslint 检查
- 遵循 Google 代码规范

## 安全规则

### 禁止事项
- ❌ 提交密钥、token、password
- ❌ 硬编码敏感信息
- ❌ 使用不安全的加密算法

### 必须遵守
- [ ] 敏感配置使用环境变量
- [ ] SQL 查询使用参数化
- [ ] 用户输入必须验证和转义

## Git 规范

### Commit Message
格式：`<type>(<scope>): <subject>`

类型：
- feat: 新功能
- fix: 修复 bug
- docs: 文档更新
- refactor: 重构
- test: 测试相关
- chore: 构建/工具

### 分支策略
- main: 生产环境
- develop: 开发环境
- feature/*: 功能分支
- hotfix/*: 紧急修复

## PR 规范

### 必须满足
- [ ] 通过所有 CI 检查
- [ ] 至少 1 人 Review
- [ ] 测试覆盖率不下降
- [ ] 无 merge 冲突

### PR 标题格式
`[类型] 简短描述`

示例：
- `[feat] 添加用户登录功能`
- `[fix] 修复内存泄漏问题`
```

## 七、最佳实践

### 7.1 配置优先级

```
项目级 > 系统级 > 默认
```

**建议**：
- 通用偏好 → 系统级
- 项目特定 → 项目级

### 7.2 渐进式配置策略

**阶段 1**：最小配置
1. 创建 `CLAUDE.md` — 告诉 Claude 你是谁
2. 创建 `rules.md` — 定义项目规范

**阶段 2**：增加自动化
3. 配置 `settings.json` — 添加钩子
4. 创建 `memory.md` — 记录经验

**阶段 3**：引入高级功能
5. 探索 skills — 自动化工作流
6. 配置 agents — 子代理并行
7. 集成 MCP — 外部工具

### 7.3 常见问题

**Q1：为什么 Claude 总是忘记我的偏好？**

A：没有配置 `CLAUDE.md` 或 `memory.md`，每次对话都是全新开始。

**Q2：如何让 Claude 遵守项目规范？**

A：在 `rules.md` 中明确定义规则，Claude 会严格遵守。

**Q3：如何防止密钥泄露？**

A：配置 `settings.json` 的 hooks，添加密钥扫描脚本。

**Q4：ECC 项目值得使用吗？**

A：如果刚开始，建议先手动配置理解机制，再考虑引入 ECC 的完整配置。
